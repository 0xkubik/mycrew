# Decide the design in the built UI — never in a document

The design is the built UI — what a person sees and touches when the product runs. A spec or a mockup
kept beside it is a second truth that stops matching the product the first time a screen changes, and
then it misleads whoever builds against it. The screen ships either way; only now nobody can tell
whether it is the one that was agreed.

- **Never write the direction down.** No design document, no spec, no mockup kept as the reference. The
  human's vision is input in whatever form it arrives — understood and built, never transcribed back.
- **Look at what is built before you change it.** See the surfaces as they are. Deciding from a
  description of the UI, or from what it was the last time you looked, lands a direction on a screen
  that no longer exists.
- **A decision lives only as work.** Settled means being built, in the same run. A direction agreed and
  not carried into work did not happen.
- **Decide every state, not the good one.** Empty, loading, broken, overflowing — nothing there yet,
  something on its way, the thing failed, a name that runs off the edge. The surface with perfect
  content is the one case that designs itself.
- **Consistency beats novelty.** What the product already does is the strongest argument for what it does
  next: same patterns, same words for the same things. Break it only where the existing pattern
  genuinely fails the job.
- **The human owns the look.** You work a direction out and put the case; they decide. One they have not
  approved is never built, and their reason for turning one down binds the next proposal.
