# Design catalog — inspiration, never copy

The designer's own domain data, kept in `data/designer/`. A designer reads the real frontend code as its
design system. The catalog is the second place to look — **reference design systems to draw ideas
from**: a proportion, a spacing rhythm, a way of handling depth, a typographic pairing.

A reference is fuel for an original composed for *this* product, never a thing to transplant wholesale.

## Ready-made DESIGN.md collections (downloaded or skimmed for inspiration)

- **[awesome-claude-design](https://github.com/VoltAgent/awesome-claude-design)** — 60+ ready design
  systems in DESIGN.md form (Stripe, Linear, Vercel, Anthropic, Apple, Spotify…). Each is a single file
  describing a visual language; read the ones near your mood to borrow decisions, not pixels.
- **[getdesign.md](https://getdesign.md/)** — the original DESIGN.md directory, searchable by vibe.

## Reference product design systems worth knowing

- **Linear** — restrained, precise, deep shadows, near-monochrome with one sharp accent. Mood:
  engineering confidence.
- **Stripe** — open, warm, generous whitespace, soft gradients used with restraint. Mood: approachable
  trust.
- **Vercel** — monochrome, tight, typographic, extremely fast to read. Mood: high-performance utility.
- **Apple/Human Interface Guidelines** — clears density, hierarchy, motion; the bar for polish and
  accessibility.
- **Material Design 3 (Google)** — the expressive token system; a complete, opinionated reference even
  if you never use M3 itself.
- **Radix/Shadcn** — accessible component anatomy and how variants + states should compose.

## Why this is a catalog, not a bundle

No system files are shipped here. Fetching them keeps the catalog lean and the licensing clean — you
reference, you draw ideas, you compose originals. If you clone a DESIGN.md to study, treat it as
reading material and keep the original attribution.
